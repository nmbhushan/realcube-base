# Platform API Observability

## Request logs

The API emits one structured JSON event per completed or failed request with timestamp, outcome, HTTP method, route template, status, duration and a request ID. The route template is used in place of the raw URL so query strings and user-supplied path segments are not copied into logs. Request IDs accept only a restricted character set and are generated by the API when the inbound header is not safe. The response includes `x-request-id` so support staff can correlate client reports with centralized logs.

The interceptor intentionally does not log request/response bodies, cookies, authorization headers, access tokens, invite tokens, emails, tenant IDs or raw exception messages. Error responses are status-only. Route templates may still reveal API structure, so centralized log access and retention must be restricted.

## Readiness checks

- `GET /api/v1/health` is a liveness endpoint; it intentionally does not require the database to be available.
- `GET /api/v1/health/ready` runs a database probe and returns `503` when PostgreSQL is unavailable. It does not expose driver messages or connection details.
- The Next.js app emits JSON security events for OIDC login start/completion/failure, state/transaction rejection, session refresh/expiry, logout, unauthenticated BFF requests, cross-origin mutation rejections and upstream API failures.
- Events contain static event/reason codes only. Never add raw callback query strings, access/refresh tokens, session IDs, email addresses or request bodies to these logs.

## Suggested alerts

In centralized logging/monitoring, alert on sustained increases in HTTP 401/403/5xx rates, repeated OIDC callback failures, repeated Redis/session-store failures, PostgreSQL readiness failures and elevated BFF 502s. Add metrics/alerts for outbox backlog and oldest unpublished event using the existing outbox worker metrics or a controlled database monitor. Set retention based on policy and restrict access to auth/security logs.

## Rollout requirements

Configure log shipping, access controls, retention, dashboarding and alert thresholds per environment. Confirm load balancer ingress logs redact callback query parameters because authorization codes and state may appear in the callback URL. Test liveness/readiness behavior under database failure. Production browser security still needs a reviewed nonce-based Content Security Policy, threat model and penetration test.
